一、核心结论

结论 1：价格不是障碍。主流独立索引 API 集中在 $1–15 / 1,000 次查询（≈¥0.007–0.11 / 次）， 中位数约 $5–7 / 1k（≈¥0.036–0.05 / 次）。一个日均 200 次搜索的 Agent，月成本 $30–42（¥216–302）； 最低档（Parallel Turbo $1/1k）月成本不到 ¥45。
结论 2：真正的差异在"计费机制"而不是"单价"。同样标价 $5/1k，可能是"每次调用固定扣"， 也可能是"模型自己决定搜几次，每次另计"（模型内置工具）、"扣 credit 且会过期"（Serper）、 或"调用费 + 检索内容 token 双计费"（OpenAI / Anthropic）。选型时必须看机制，不是看单价。
结论 3：2025–2027 三条供给线在消失。 Bing Search API 已 2025-08-11 退役（只剩 Azure Grounding，且官方明确"输出不得用于其他应用"）； Google Custom Search JSON API 已对新客户关闭、据多方报 2027-01 关停； "转卖 Google SERP"的代抓厂商（Serper / SerpApi）是当前唯一能拿到"和 Google 一致结果"的路径，但属法律灰色地带。 长期稳定的只剩独立索引（Brave / Kagi / Exa / Parallel）与云厂商第一方。
结论 4：对 inputlab 这种"自建 CDP 抓 Google"的架构，临界点大约在 每月 2,000–3,000 次查询：低于它，自建（现金零成本）划算；高于它， 一次封禁/一次改版的人力成本就超过全年 API 费用。建议：API 为主、CDP 为兜底， 而不是二选一。

七、覆盖率与索引规模

假设 Google 为基线。覆盖率不像价格那样公开，但有三类可查迹象：① 厂商自报索引规模；② 索引来源（自有 / 授权 / 聚合 / 代抓）；③ 第三方测量的重叠度与质量分。

先纠正一个直觉：覆盖率不是「索引了多少页」，而是「索引了哪些页」。 学术测量显示 Google 与 Bing 的 top-1 结果重叠只有 31%，整体重叠始终低于 32%（Yagci et al. 2022）； AI 助手引用的链接里只有 12% 出现在 Google 同一问题的 top 10，80% 在 Google 上完全没有排名（Ahrefs 2025，15,000 条 prompt）。 也就是说：即使被公认为「最强」的 Google，也覆盖不到另一个引擎能覆盖的页面——覆盖率问题的正解是多来源组合，不是「选一个最大的」。

7.1 索引规模（厂商自报口径）

Google 官方只写「hundreds of billions of webpages / well over 100,000,000 gigabytes」，从不给精确页数——图中 300B 为区间示意。 Bing 从未公布规模，8–14B 为第三方估算。注意：规模条的长度差异（Google ∼300B vs Mojeek 9B）不能解释它们与 Google 的重叠度差异。

7.2 索引来源分类（决定供给稳定性）

自有索引不怕别人断供；代抓 Google 的同时承担法律与供给风险（Google 已于 2025 年对 SerpApi 提起诉讼）。

7.4 对选型的三个含义

① 覆盖率只能靠组合，不能靠单选。要「尽量不漏」就应该用两家不同来源的索引（例如 Brave 自有索引 + 一家 Google 系）， 它们之间重叠很低，组合后的召回显著高于任何单一引擎。
② 「索引规模」是最弱的指标。Brave 40B 与 Mojeek 9B 差 4 倍，但两者与 Google 的重叠都远低于 50%—— 规模差异 ≠ 覆盖差异，要测的是「对你的查询集的命中率」。
③ 中文/非英语是另一条轴。Google、Brave、Mojeek 对中文长尾的覆盖都弱于百度系； 国内云厂商的价值主要在中文内容与合规，而不是索引规模。

7.5 如何自测覆盖率（可复现探针方法）

厂商不公布覆盖率，但用一小组「锚点」在几小时内就能测出对自己场景的覆盖率与互补性。

最小可行实验：准备 30–50 个「已知答案页面」（收藏夹、站点 sitemap、近一周新发布页面、冷门专有名词）， 为每页写一条不含域名的查询，逐家 API 跑同一批查询，统计 recall@10（目标页是否进前 10）与 MRR（目标页的平均倒数排名）。再以 Google 为基线，算「其他引擎召回了多少 Google 没召回的目标页」—— 互补率比覆盖率更能指导选型。
诚实说明：没有任何搜索厂商公布真实覆盖率；索引规模是营销口径，「更多页面」不等于「更好召回」。 本节规模数字全部来自厂商官网/官方博客原文或第三方公开估算；重叠度数字来自学术论文与第三方研究， 均为特定查询集上的测量，不可外推为普适覆盖率。Google 作为「最强」是本节的假设基线，不是测量结论。

十一、数据分析

价格带分布

单位经济学换算

四个观察

  1. 价格收敛在 $5/1k。$5/1k（≈¥0.036/次）几乎成了行业锚点：Brave、Perplexity Search、You.com、 Tavily 订阅档、Exa 的 Answer、Parallel 的 Basic 全部落在这一档。差异化不在价格，而在 索引质量、延迟、吞吐上限、是否 ZDR。
  2. 抽取（读正文）比搜索便宜一个数量级。Contents / Extract 类接口普遍 $1/1k 页（Exa、You.com）、$4/1k（Kagi）、$0.83–3.2/1k（Firecrawl 按档位）。 这意味着"搜索贵、读取便宜"——把预算花在"搜得准"，而不是"抓得多"。
  3. 云厂商在国内并不便宜。火山 ¥20/千次、腾讯轻量 ¥18/千次、阿里极速版 ¥12/千次， 折算 $1.67–2.78/1k——比 Brave 便宜，但比 Serper（$0.3–1/1k）贵 3–9 倍，且要走 QPS 报备/阶梯/日结。 国内价的价值在合规、可用性、中文内容覆盖，不在单价。
  4. 模型内置工具是最贵的一档，且成本不可预测。OpenAI $10–25/1k + 检索内容 token； Anthropic $10/1k + token；Gemini $14/1k search query。Gemini 官方页明确 "客户向 Gemini 提交的请求可能触发一次或多次 Google 搜索查询，每执行一次搜索查询都会单独计费"—— 也就是说一次用户提问可能扣 N 次搜索费。
注意 Gemini 页面的一个例外条款（对成本有利）：官方定价页写明 "通过'依托 Google 搜索进行接地'功能检索到的上下文（文本或图片）不计入输入 token 费用"—— 这与 OpenAI / Anthropic"调用费 + 内容 token 双计费"形成鲜明对比。

十二、自建 CDP 抓取 vs 采购 API：TCO 对比

自建侧假设：本机/服务器成本按 ¥0（已有 Mac）～¥50/月（VPS）计；维护工时按每月 4 小时 × ¥200/小时 （故障排查、验证码对抗、页面改版适配）计；封禁风险按"每季度一次需半天恢复"摊薄。 API 侧按 Brave $5/1k 计算，不含 token 费。结论：约 2,000–3,000 次/月是分界线。

附录 A：法律风险（美国）

问题：以「人类方式驱动真实浏览器」（不黑入、不破坏防御、不自动过验证码、不绕登录墙）是否招致更多美国法律诉讼？ 方法：检索并逐篇核实美国判例与成文法；抓取时间 2026-09-17。

结论：没有找到任何以「模拟人类操作」本身作为违法事由或判决依据的案件或法规。 检索到的所有相关诉讼，诉因都是：绕过技术措施、违约、转售数据、假账号——不是输入方式。 反而在 2026-08 出现了一条对你有利的上诉判例（Amazon v. Perplexity）： 代理厂商「替用户操作浏览器」时，CFAA 下的访问者是用户，厂商不承担 CFAA 责任。
三条风险线（只需要盯这三条）：
① 合同：违反 ToS → 禁令 + 赔偿（hiQ 赢了 CFAA 却赔了 $500,000）；
② 撤销授权后继续：收到 C&D / 被 IP 封锁后仍继续（尤其换 IP、代理、账号）→ CFAA 成立；
③ 规避技术保护措施：绕 CAPTCHA / 限流 / 登录墙 / 付费墙 → CFAA + DMCA §1201（+ 票务场景的 BOTS Act）。

A.4 2025–2026 态势

  • 平台执法重心从 CFAA 转向 ToS + 技术措施 + 反规避（DMCA §1201）+ 付费抓取（Cloudflare pay-per-crawl）。 Google 诉 SerpApi 的核心诉因就是这个组合，而不是「你像个机器人」。
  • 法院开始区分「代理厂商 vs 用户」。第九巡回在 Amazon v. Perplexity 中把 CFAA 的「访问者」认定为用户， 并援引 rule of lenity；这直接支持「用户侧浏览器自动化」的架构。但该判决限缩于当前记录， 法院同时提示平台方今后应依赖 ToS 限制 + 技术措施。
  • 诉讼总量确实在增加：Google v. SerpApi（2025-12）、Reddit v. Anthropic（2025-06）、 Reddit v. Perplexity（2025-10）、News Corp v. Perplexity——但诉因都是「绕过措施 + 违约 + 转售」。
  • 最大的未决变量：第三巡回对 Ryanair v. Booking.com 的态度。地院法官认为「C&D 后访问公众用免费账号就能拿到的信息」也构成 CFAA， 与第九巡回的 hiQ 路线相左；上诉未决。
